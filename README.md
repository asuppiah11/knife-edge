# Knife-Edge

**The next goal changes everything. Knife-Edge tells you by how much — before it's scored.**

Knife-Edge is a live football match-intelligence engine that measures how much every moment matters and explains it in plain language. Instead of a win-probability line, it reads the match like a sensitivity model:

| Greek | Question it answers | Shown as |
|---|---|---|
| **Delta** | How far did that moment move the match? | `+14.2 pts` swing per event; `xG × delta` expected swing for every shot |
| **Gamma / knife-edge** | How fragile is the game right now — how much would the *next* goal swing it? | `next goal swings 38 pts` fragility meter |
| **Theta** | How fast is time working for the team in front? | `+0.58 pts/min` for the leader |
| **Vega** | Who benefits if the game opens up? | `chaos favours Mossridge: +13 pts` |

A crew of agents (Quant, Tactician, Narrator, Localiser, Verifier) turns those readings into timed broadcast overlay cues, personalised fan cards in **English, Spanish and Tamil**, and a **bench mode** that gives coaching staff at most three evidenced prompts per half. A deterministic Verifier grounds every number and name against the event log before anything reaches the screen.

> Entry for *Inside the Game: Developer Hackathon* (Microsoft × Premier League). All data is synthetic: the league, clubs, players and matches are generated by `knifeedge.sim` and no real competition data, names or marks are used. No odds, no betting: probabilities are model estimates of the match state.

## How it maps to the brief

| Brief stage | What Knife-Edge does | Where |
|---|---|---|
| **Ingest** events as they happen | SSE replay of a synthetic event log at match speed; MCP + REST for agents | `knifeedge/api` |
| **Interpret** into stats, patterns, context | xG, pass difficulty, PPDA, field tilt, pressures, sprint tagging; live intensity model with explainable multipliers | `knifeedge/engine` |
| **Explain** why a moment matters | Closed-form win probability + Delta/Gamma/Theta/Vega; every swing decomposed into time, momentum, discipline, score | `engine/greeks.py`, `engine/replay.py` |
| **Render** timed, machine-readable overlays | Overlay cue contract (`t_in`, `t_out`, priority, evidence ids, facts) a rendering partner can draw | `schemas/overlay_cue.schema.json` |
| **Personalize** | Casual / Analyst / Bench / Player-focus modes, EN/ES/TA | `knifeedge/agents` |
| **Data innovation** | Seeded synthetic league with hidden tactical regimes and published calibration | `knifeedge/sim`, `docs/model-report.md` |

## Quick start (no cloud needed)

```bash
pip install -e ".[dev,mcp]"
knife-edge season  --out data/ratings.json              # synthetic season -> pre-match ratings
knife-edge generate --seed 42 --out data/matches/KE-000042
knife-edge replay   data/matches/KE-000042 --ratings data/ratings.json
knife-edge cues     data/matches/KE-000042 --ratings data/ratings.json --audience bench --lang es
knife-edge serve    --matches data/matches --ratings data/ratings.json   # http://localhost:8000
pytest
```

`knife-edge serve` hosts the REST API, the MCP tool server at `/mcp`, and the studio UI at `/` (no build step; Three.js and the two typefaces are vendored under `web/vendor` and `web/fonts`, so it also runs offline):

* **Scorebug** on a light studio wall: generated crests, the match clock, a state chip (knife-edge / fragile / settled / decided, or 11 v 10) and a live home / draw / away probability bar with animated numbers.
* **The Greeks band**, the heart of the page: Delta (how far the last shot or card moved the match), Knife-edge (how far the next goal would, with a gauge), Theta (what each quiet minute is worth to the side in front) and Vega (who gains if the game opens up), each as a big number, a football-language sentence and a sparkline across the match that reveals as the clock runs. **What-if** buttons under it call the engine for a goal, a red card or a more open game at the current minute and show before → after bars.
* **3D pitch** (WebGL) — at every shot a low-poly player in the kit, frozen mid-strike and facing the goal they attacked; a disc under them for the chance size (xG) and a pillar beside them for its Delta, coloured by the side that gained, gold for goals with the ball's arc into the net; the values float above the big ones. A figure runs with the ball carrying the player's name and number; the last passes and carries fade on the turf; chances older than fifteen minutes ghost out. Drag to orbit, scroll to zoom, or jump between **Broadcast**, **Overhead** and the two **goal-end** cameras (keys 1–4). Hover a shooter for the chance, click to see why it moved the match. Machines without WebGL (or `?flat=1`) get the flat pitch instead.
* **Transport** — play at 15× to 400×, scrub to any second, or hover the probability river to read the state at any minute and click to jump there. **Biggest moments** chips jump straight to the swings that mattered. Space, ← and → work too.
* **Overlay cue** lower-third that fires at each cue's `t_in`, the cue list, and **Simulate a bad narrator**, which swaps in a model that invents numbers so you can watch the Verifier block two drafts and fall back to the template.
* **Pressure** — last-10-minute field tilt with recent xG, two-sided team stat bars, the filterable match feed (goals / shots / cards / subs) and player cards (shots, Delta from shots, chances worth, top speed, sprints).

Template mode needs no model; set `FOUNDRY_ENDPOINT` to switch the Narrator and Localiser to a Foundry-hosted model (see `docs/azure.md`).

## Architecture

```
 synthetic league ──► events.jsonl ──► engine (ratings · WP · Greeks · replay) ──► REST + MCP + SSE
   (sim/, seeded)        match.json        │                                           │
                         truth.json        │ facts, evidence ids, Greeks               │ tools
                         (hidden)          ▼                                           ▼
                                   Quant ∥ Tactician ──► Narrator ──► Localiser ──► Verifier ──► overlay cues
                                   (moment selection,     (Foundry     (ES / TA)     (deterministic;   (casual · analyst ·
                                    bench prompts)         model)                     retry ➜ template)  bench · player)
```

* **Engine** — remaining goals as two Poisson processes whose intensities come from fitted team ratings × score state × men on the pitch × an age-weighted momentum term (recent xG vs expected, field tilt). Greeks are finite differences on the closed-form probabilities, so they are exact for the model.
* **Agents** — `knifeedge/agents/pipeline.py` runs the roles in-process with an injected LLM; `agents/foundry_runner.py` is the Microsoft Agent Framework workflow (Concurrent → Sequential) that calls the same engine through the Greeks MCP server.
* **Verifier** — numbers, names, minute labels, scorelines, vocabulary and evidence ids are checked deterministically; an LLM draft that fails is retried once with the rejection reasons, then replaced by the template. See `tests/test_agents.py` for the fault-injection tests.

## Model report (synthetic league, 500 matches)

| Model | Brier (3-way) | RPS | ECE P(home) |
|---|---|---|---|
| pre-match frozen | 0.655 | 0.228 | 0.072 |
| live (score, clock, cards) | 0.478 | 0.155 | 0.037 |
| **live + momentum (full engine)** | **0.478** | **0.154** | **0.035** |

Full tables and the reliability diagram: [`docs/model-report.md`](docs/model-report.md). Known limitation: the engine slightly over-rates a side on 55–65% (observed ≈ 46–57%), because its score-state multipliers are deliberately not the simulator's; this is the kind of mis-specification a real model faces.

## Responsible design

* Synthetic only: `match.json` carries a provenance statement; `truth.json` is never read by the engine.
* No betting: the Verifier rejects odds/price/market vocabulary; the UI never shows odds; probabilities are labelled as model estimates.
* Explain real events, never invent: every cue carries `evidence_event_ids` and the only numbers it may contain.
* Accessibility and reach: plain-language casual mode, three languages, machine-readable cues for audio description.
